# 项目协作规约 · 瓦洛兰特模型转换

> 本文件是本项目的协作约定，所有参与方（AI 实现者、人类顾问、后续接手者）开工前必读。
> 有新增约定时在此追加，并同步到 `.workbuddy/memory/MEMORY.md` 一行摘要。

## 角色分工（2026-10-13 确立）
- **顾问/军师**（用户）：架构决策、代码审阅、放行把关；不主力编码。
- **实现者**（workbuddy）：改代码、出方案与 diff、执行本地检查（py_compile 等）；不做 UE 内实测。

## 流程规约

### 1. 关键 review 独立消息重发确认（2026-10-13 教训）
本日发生过军师关键补审（①-⑦）传输丢失、实现者未收到导致一轮空转。约定：
- **任何含放行/否决结论的 review，发送后应在下一条消息确认对方已收到**（"上一轮 review 收到请回执"）；
- 实现者收到 review 后，若内容与预期不符（如声称"重复投递"），先怀疑传输层丢消息，主动索要原文，不要按字面理解硬接。

### 2. 放行流程
实现者改码 → `py_compile` 通过 → 出 diff（统一格式：相对原始交付件的 `diff -u`）→ 军师审 → 放行 → 议题关闭、patch 归档。**未放行的代码不得作为基线。**

### 3. 双端契约改动
gun_type 枚举、命名正则、配件/弹匣关键词等双端契约改动，必须同一轮同步 Blender 侧与 UE 侧，并在 `交接文档.md` 第四节登记。

### 4. 设计决策留痕
实现者做出的自主决策（如 Map/ 排除、白名单为空保守排除），必须在回复中显式标注"自主决策，请军师补审"，不得静默埋进代码。

### 5. 状态记录
- 每轮实质工作后更新 `交接文档.md` 对应小节 + `.workbuddy/memory/` 当日日志；
- patch 归档命名：`P{n}-{n}_review.patch`，含议题编号与行数。
